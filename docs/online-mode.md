# 联机模式说明

## 启动

```bash
npm install
npm run dev
```

前端默认会连接“当前页面所在主机”的 `8787` 端口。

例如你在主机电脑上用局域网地址打开：

```text
http://192.168.3.43:5173
```

那么联机 Socket 会自动连接：

```text
http://192.168.3.43:8787
```

如果后端地址不同，可以显式设置：

```bash
VITE_SERVER_URL=http://192.168.3.43:8787 npm run dev:client
```

## 局域网联机

1. 主机电脑运行 `npm run dev`。
2. 查看主机电脑的局域网 IP，例如本机当前是 `192.168.3.43`。
3. 其他电脑打开 `http://192.168.3.43:5173`。
4. 所有人进入“联机模式”。
5. 主机电脑创建房间，其他电脑输入同一个房间号加入。

不要让其他电脑打开 `http://localhost:5173`。在其他电脑上，`localhost` 指的是它自己，不是主机电脑。

## 本地双浏览器测试

1. 打开 `http://localhost:5173`。
2. A 浏览器进入“联机模式”，输入昵称，创建房间。
3. 复制房间号。
4. B 浏览器或无痕窗口进入“联机模式”，输入昵称和房间号，加入房间。
5. B 点击准备。
6. A 作为房主点击开始游戏。
7. 服务端自动补足 AI 到 4 人。
8. 两个浏览器会看到同一个城邦、回合、公共玩家状态，但只能看到自己的手牌和商店。

## 当前联机规则

- 采用同步回合制。
- 每名真人玩家同时操作自己的私有商店和手牌。
- 当前版本没有备牌区；手牌满 14 张后不能继续购买，需要先弃 1 张。
- 每名玩家每回合只能弃 1 张牌，弃掉的牌会回到公共牌库。
- 服务端保存权威 `GameState`。
- 客户端只发送操作意图。
- 所有操作通过 ack 返回成功或错误。
- 每名玩家的私有商店由服务端强制规范化，最多 5 张牌；锁店也不能超过 5 张。
- 锁住的商店牌不会回到公共牌库，其他玩家刷新不到这些被锁住的实例。
- 所有真人玩家结束回合，或服务端倒计时结束后，统一结算。
- AI 由服务端补位并参与结算。
- 多人同时胡牌时，服务端按胡牌战力分判定本回合胜者。
- 游戏结束排名按淘汰顺序稳定结算，越晚淘汰名次越高。
- 玩家淘汰或整局结束时，客户端会展示全局结算弹窗。

## 重连

- 创建或加入房间后，客户端保存 `sessionToken` 到 `localStorage`。
- 断线后服务端将玩家标记为离线。
- 60 秒内重新连接并发送 token，可以恢复房间和游戏状态。
- 当前版本实现基础恢复，超时后会拒绝重连；AI 托管的长期策略留到后续版本扩展。

## 当前限制

- 房间和游戏状态存于内存，服务重启会丢失。
- 未接入账号、匹配、聊天、观战、排行榜。
- 暂不做多服务器同步。
- AI 托管逻辑较简单。
- UI 已能完成联机操作闭环，但移动端未深度优化。
- 当前没有房间持久化，游戏结束后的房间清理仍以服务端内存生命周期为准，后续可接入更明确的房间 TTL/销毁策略。
