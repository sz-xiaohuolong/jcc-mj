# 积分与排行榜系统

当前版本实现第一版轻量积分系统，不接入账号数据库。

## 玩家身份

浏览器会在本地生成长期身份：

- localStorage key：`jcc-mj-profile-id`
- value：`crypto.randomUUID()`

`profileId` 用于区分同一浏览器里的玩家积分。`sessionToken` 只用于联机房间重连，不作为长期玩家身份。

当前限制：清理浏览器 localStorage、更换浏览器或更换设备后，身份和本地单机积分会丢失。这不是强账号体系。

## 单机积分

单机积分保存在浏览器 localStorage，和联机积分分开统计。

| 最终排名 | 积分变化 |
| --- | ---: |
| 第 1 名 | +30 |
| 第 2 名 | +10 |
| 第 3 名 | -10 |
| 第 4 名 | -20 |

最低积分为 0，不会扣成负数。

单机保存信息：

- `profileId`
- `nickname`
- `soloPoints`
- `soloMatches`
- `soloWins`
- `highestHuScore`
- `matchRecords`

单机中，当玩家获胜或生命值归零时，会结算本局积分并在最终弹窗中展示：

- 本局排名
- 积分变化
- 积分变化前
- 积分变化后
- 当前段位

## 联机积分

联机积分由服务端权威结算，前端不能提交积分结果。

服务端根据 `GameSessionManager` 的最终 `ranking` 计算积分，只在正常 `game_over` 时结算。AI 不进入联机排行榜。

| 最终排名 | 基础积分变化 |
| --- | ---: |
| 第 1 名 | +40 |
| 第 2 名 | +20 |
| 第 3 名 | 0 |
| 第 4 名 | -20 |

联机真人数量倍率：

| 真人数量 | 倍率 |
| --- | ---: |
| 4 名真人 | 1.0 |
| 3 名真人 | 0.8 |
| 2 名真人 | 0.5 |
| 1 名真人 | 0 |

积分变化会四舍五入为整数。最低积分为 0。真人玩家少于 2 名时，不计入联机积分。

同一个 `profileId` 在同一个房间内只会计分一次，防止重复身份重复计分。

## 排行榜

首页提供“排行榜”入口。

排行榜分为：

- 单机榜：读取当前浏览器 localStorage 的单机积分。
- 联机榜：从服务端 `/leaderboard` 读取内存/文件持久化的联机积分。

显示字段：

- 排名
- 昵称
- 段位
- 积分
- 胜场
- 对局
- 胜率
- 最高胡牌战力

## 存储方案

单机：

- 浏览器 localStorage。

联机：

- 服务端内存 Map。
- JSON 文件持久化：`data/rating_profiles.json`。
- 对局记录 JSONL：`data/rating_match_records.jsonl`。

这两个运行时数据文件已加入 `.gitignore`，避免把本地积分数据提交到仓库。

## 当前限制

- 没有账号登录，`profileId` 可被清除或复制。
- 不支持跨设备同步。
- 联机排行榜只适用于当前服务端数据文件。
- 没有赛季、匹配分、隐藏分或防作弊审计。
- 第一版没有复杂表现分，只记录最高胡牌战力。
