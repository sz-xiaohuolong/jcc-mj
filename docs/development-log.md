# 开发日志

## 需求分析

目标是从 0 到 1 实现一个 Web 单机小游戏 MVP：麻将胡牌是胜利目标，自走棋式商店、经济、羁绊、海克斯、城邦构成构筑循环。

第一版明确不做联网、后端、登录、排行榜、真实 IP 素材、复杂番型、吃碰杠和完整四人摸打。

## 方案设计

技术栈：

- React + TypeScript + Vite
- Zustand
- Tailwind CSS
- Framer Motion
- Vitest

模块边界：

- `data`：原创静态配置。
- `engine`：纯规则模块，便于测试。
- `store`：串联游戏动作。
- `components/pages`：展示与交互。

## 任务拆解

1. 初始化工程和测试工具。
2. 先写胡牌、商店、羁绊、AI、主流程测试。
3. 实现类型、静态配置和 engine。
4. 实现 Zustand store。
5. 实现首页、游戏页、规则页和弹窗。
6. 使用 frontend-design 准则优化视觉。
7. 补 README、规则文档和开发日志。
8. 运行测试、构建和浏览器 smoke test。

- 第三版规则调整：
  - 多人同时胡牌时比较胡牌战力分。
  - 低分胡牌者按分差少量扣血。
  - 弃牌和出售牌回到公共牌库。
  - 移除备牌区玩法，手牌满 14 张后不能继续购买。
  - 每名玩家每回合只能弃 1 张牌。
  - 降低低费牌羁绊密度，高费牌才保留双羁绊上限。
- 第四版 AI 与联机稳定性增强：
  - 新增 `src/engine/aiHandEvaluator.ts`，AI 会评估普通胡、七对子、碰碰胡、清一色路线。
  - AI 手牌满 14 张且未胡牌时，会主动出售弱牌腾空间。
  - AI 接近胡牌或低血量时更积极刷新，中后期金币充足时适当升级。
  - AI 海克斯选择会参考对子、刻子、花色集中度、血量和经济状态。
  - 联机玩家刷新或重连导致的重复玩家问题已通过房间/连接管理测试覆盖。
  - 联机私有商店新增服务端规范化，强制最多 5 张，并避免锁店牌进入其他玩家商店。
  - 游戏结束排名改为按淘汰顺序稳定结算。
- 第五版音频与结算体验：
  - 新增轻量音效系统、音效开关和音量设置。
  - 引入 Kenney Interface Sounds 作为 CC0 操作音效来源。
  - 引入 OpenGameArt `relax_background1` 作为 CC0 无歌词循环 BGM。
  - 音效音量和 BGM 音量分开控制，BGM 在首次用户交互后启动。
  - 整理手牌音效替换为更安静的短反馈。
  - 新增胜利 / 死亡 / 最终排名全局弹窗。
  - 提高每回合结算弹窗背景和文字对比度。

## 遗留问题

- AI 和玩家暂时共用简化商店流，后续可改为 AI 私有行动上下文。
- 海克斯部分效果当前作为标签和后续扩展入口，未全部做成强效果。
- 经验购买机制尚未完整展开。
- 图鉴入口暂时复用规则页，后续应独立为图鉴页。
- 联机状态当前使用内存存储，服务重启会丢失房间。
- 游戏结束后的房间持久化/自动销毁策略仍需产品化定义。
- 断线超时后的 AI 托管策略仍较轻量，后续需要更完整的托管行为。
- 音频目前只有一条 BGM，没有按城邦或阶段做动态音乐。
- 暂未接入 Redis、数据库、账号、匹配和排行榜。
